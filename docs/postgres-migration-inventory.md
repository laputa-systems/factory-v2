# PostgreSQL migration inventory

This is the checked migration ledger for the hard cutover described by
[POSTGRES-MIGRATION-PLAN.md](../POSTGRES-MIGRATION-PLAN.md). The source fresh
bootstrap is 2,417 lines (2,435 after the CL-001 runtime-binding additions in
this branch). The PostgreSQL migration is intentionally fresh-only: ignored
SQLite prototype files are disposable and no importer exists.

## Phase 1 contract

- [x] `migrations/postgres/0001_kernel.sql` is the sole canonical PostgreSQL bootstrap.
- [x] 322 source tables are represented as PostgreSQL tables; internal numeric identities use `BIGINT GENERATED BY DEFAULT AS IDENTITY`, binary identities use `BYTEA`, and text fields remain explicit `TEXT`.
- [x] 727 source foreign-key references are named PostgreSQL foreign-key constraints.
- [x] 8 source partial/functional indexes are retained.
- [x] Bootstrap rows are inserted explicitly and all identity sequences are advanced after those inserts.
- [x] SQLx migration state is recorded in the private schema's `_sqlx_migrations` table; a second migration run validates the checksum without replaying DDL.
- [x] The synchronous shell owns one current-thread Tokio runtime and a bounded pool; schema search path is set after connection and before every pool acquisition.
- [x] A resident advisory lock holds one dedicated checked-out connection for the guard lifetime; contention is tested on independent stores.

## Trigger and invariant evidence

- [x] Source cross-row/immutability triggers are represented by 24 PostgreSQL triggers and PL/pgSQL functions: object-revision immutability and kind matching; capability-grant principal bindings; the single supervisor epoch; Pi sidecar requirements; live PID/PGID reuse exclusion; liveness reappearance containment; and the four-way Pi accounting sequence namespace.
- [ ] Phase 2 must preserve every trigger's observable rejection while porting the transition SQL; no domain policy may be inferred from PostgreSQL error text.
- [ ] Phase 2 must add real-database regression cases for duplicate command IDs, same-ID/different-body idempotency, stale generations, rejected-command durability, and each trigger replacement.

## Transaction and identity sites

- [x] The SQLite transaction envelope is located in `KernelStore::execute` and `execute_in_transaction` (`crates/society-kernel/src/store.rs:1042-1180`): command identity/fingerprint lookup, existing-receipt resolution, typed body persistence, accepted/rejected command/event persistence, materialized transition, and commit.
- [x] Replay and materialized validation are `replay_ledger` and `validate_replayed_materialized_state` (`store.rs:1243-1375`).
- [ ] Port these as one SQLx `PgTransaction` envelope, preserving source order and atomic commit.
- [ ] Replace all three `last_insert_rowid` sites with statement-local `RETURNING`: `store.rs:1123` (command row), `store.rs:11380` (shared study/transition helper), and `study.rs:1276` (study identity helper).
- [ ] Audit every SQLite `Immediate` transaction and retain serial daemon dispatch or add a narrowly justified row lock/serializable retry.

## Phase classification

- **Schema:** the 322 tables, 727 foreign keys, 8 indexes, 24 triggers,
  identity sequence reset, seed rows, and SQLx migration ledger above.
- **SQL helper:** `KernelDatabaseUrl`, redacted errors, bounded pool,
  current-thread runtime, search-path callbacks, catalog snapshot, and the
  dedicated advisory-lock guard in `crates/society-kernel/src/postgres.rs`.
- **Behavioral-test evidence:** `postgres_harness.rs` proves fresh/second
  migration and advisory-lock contention; `postgres_schema_contract.rs` proves
  catalog cardinalities. Phase 2 adds the complete transition/replay and
  invariant regression evidence.

This inventory is deliberately a checklist: unchecked Phase 2/3 items are
migration gates, not claims that the SQLite implementation is already portable.
