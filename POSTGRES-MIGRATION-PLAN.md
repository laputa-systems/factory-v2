# PostgreSQL / SQLx hard-migration plan

## Outcome

Replace SQLite `KernelStore` with PostgreSQL through SQLx. PostgreSQL becomes
the sole mutable ledger authority for `societyd`, `societyctl`, CL-001, and all
tests. There is no store trait, driver switch, dual write, or SQLite fallback.

## First decision: reset or preserve

**Recommended:** treat the present ignored `var/` SQLite databases as
disposable prototype state. Archive independently required research artifacts,
create PostgreSQL fresh, and rerun founding/CL-001 setup. This is faster and
more rigorous than presenting unverified prototype state as migrated evidence.

If any SQLite ledger must survive, stop and create a signed inventory of source
database digest, required content roots, every table, row counts, FK order,
and command/event/replay digests. The one-shot importer in phase 5 is then
required. It is never an application database mode.

## Fixed implementation choices

- Retain typed domain values and Unix-socket protocol; this is storage only.
- Retain internal numeric IDs as `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
  Replace each `last_insert_rowid` with statement-local `INSERT ... RETURNING`.
- Keep numeric state/kind codecs with explicit `CHECK` constraints and use
  `BYTEA` for binary identities.
- Approve and exact-pin SQLx, one async runtime, and Rustls TLS in
  `DEPENDENCIES.md` before dependency changes. No ORM.
- Convert `KernelStore` and private transaction helpers to async through the
  workspace. Do not conceal SQLx in per-method `block_on` calls.
- Replace the SQLite runtime file lock with one PostgreSQL advisory lock held
  for daemon lifetime. It complements, never replaces, row locks.
- Use a real PostgreSQL database named by `SOCIETY_POSTGRES_TEST_URL`; no mock
  driver. PostgreSQL 18 from Homebrew is the local development baseline.

## Phase 1 — inventory, dependency approval, and test harness

- Commit `docs/postgres-migration-inventory.md`: map the SQLite ABI-27 schema
  in `migrations/0001_kernel.sql`, all `KernelStore` callers, transaction
  boundaries, and every SQLite-specific feature (`Immediate`, savepoints,
  `last_insert_rowid`, pragmas, partial indexes, placeholders).
- Add approved exact SQLx/runtime/TLS dependencies and `KernelDatabaseUrl`.
  Reject empty/invalid URLs and TLS-disabled remote URLs.
- Add a test-only real-PostgreSQL harness creating an isolated database/schema,
  applying migrations, and cleaning it after serial integration suites.

Nearest judge: `SOCIETY_POSTGRES_TEST_URL=... cargo test -p society-kernel --test postgres_harness -- --test-threads=1`.

## Phase 2 — PostgreSQL schema, no textual SQL conversion

- Replace the one SQLite bootstrap with ordered `migrations/postgres/` SQLx
  migrations. Translate every table, FK, `CHECK`, unique/partial index, and
  identity deliberately; name each constraint/index.
- Add an advisory-locked migration coordinator and supported schema-revision
  check before daemon command acceptance.
- Add catalog-contract tests for command idempotency, ledger ordering, FKs,
  partial uniqueness, and all critical state constraints.

Nearest judge: a fresh database migrates twice and schema-contract tests pass.

## Phase 3 — port the kernel transaction envelope, then transition families

- Replace `rusqlite::Connection` with bounded `sqlx::PgPool` in
  `crates/society-kernel/src/store.rs`; make public and private store methods
  async. Port external callers in the same series.
- First port command idempotency, rejected placeholder, command body rows,
  savepoint rollback, accepted event, and materialized projection as one
  transaction. Preserve every typed `Rejection`.
- Port query/transition families in ledger order. Use `SELECT ... FOR UPDATE`
  for state/generation guards, `RETURNING` for writes, and bounded whole-command
  retry only for documented serializable budget/admission operations.
- Replace `?N` with `$N`, `BLOB` with `BYTEA`, and SQLite row decoding with
  narrow typed SQLx decoders. No dynamic SQL maps.

Nearest judge: existing replay/materialized audit runs after each family; add
real PostgreSQL tests for duplicate command IDs, stale generation, rejection
durability, competing claims, and concurrent budget reservations.

## Phase 4 — move daemon, harness, and tests

- Replace `runtime_root/society.sqlite3` opening/permissions with
  `KernelDatabaseUrl`, migration check, replay check, and advisory lock.
- Preserve content-root and socket ownership protections.
- Move `societyctl`, daemon protocol tests, CL-001 harness, content,
  evaluator, and Pi execution fixtures from `open_in_memory`/filesystem DBs
  to the PostgreSQL test harness.

Nearest judges: kernel tests, then `cargo test -p societyd --test supervision -- --test-threads=1`, then workspace tests using the real URL.

## Phase 5 — one-way cutover

**Reset path:** stop the daemon, archive required artifacts, initialize fresh
PostgreSQL, start only the PostgreSQL daemon, then rerun founding/CL-001 setup.

**Preservation path:** build a separately compiled `society-sqlite-import`
tool. It accepts only read-only copied SQLite input, verifies source digest and
replay, imports tables in explicit FK-safe order preserving IDs, resets
identities, and proves exact table counts plus command/event/replay digests.
It cannot start a daemon or accept commands. Delete it and `rusqlite` after the
recorded migration window.

## Phase 6 — remove SQLite authority and finish

- Delete `rusqlite`, bundled transitive graph, SQLite migrations,
  `society.sqlite3`, `open_in_memory`, runtime database-file checks, and all
  SQLite setup docs.
- Update `AGENTS.md`, `DEPENDENCIES.md`, `ARCHITECTURE.md`, `README.md`, and
  test instructions to name PostgreSQL as sole authority.
- Add PostgreSQL health, migration revision, backup/restore, and replay checks
  to daemon diagnostics.

Final checks:

- Search for `rusqlite`, `sqlite3`, `PRAGMA`, `open_in_memory`, and
  `society.sqlite3` in active code/dependencies/tests. Only documented archive
  history may remain.
- Run `cargo fmt --all --check`.
- Run `cargo test --workspace --all-features`.
- Run `cargo clippy --workspace --all-features --all-targets -- -D warnings`.
- Run `tests/generic-boundary/run-no-application-knowledge.sh`.

A clean PostgreSQL restore must pass ledger replay/materialized-state validation
before a daemon can accept commands.

## Agent discipline

- One cohesive commit per numbered phase—not formatting or exploration commits.
- Do not parallelize `store.rs`; at most one secondary agent ports a
  pre-enumerated disjoint transition family with tests.
- Run nearest kernel/daemon judge during a phase; run full workspace gates only
  at phases 4 and 6.
- A conversion failure never justifies loosening a constraint or turning a
  database error string into domain policy.
